# Storage cleanup audit — 2026-08-20

## Decisions

| Target | Pre-clean size | Safe to remove completely? | Action |
|---|---:|---|---|
| `hexagon-mlir/benchmark_models/*.mlirbc` | 5.2 GiB | Yes | Remove; all files are untracked runner-generated exports. |
| `LLVM_DIR` | 15 GiB | Yes, after preserving its dirty patch | Preserve the two-file diff under `third_party_software/patches/`, repoint `LLVM_DIR_upstream` to the official LLVM remote, then remove. |
| `LLVM_DIR_upstream` | 9.3 GiB | No | Keep; the active CMake cache, build scripts, headers, tools and libraries use this tree. |
| `hexagon-mlir-legacy` | 16 GiB | No | Keep the repository because it has dirty tracked sources and unique untracked research material. Remove only reproducible build/cache/MLIR bytecode artifacts. |
| `hexagon-mlir-native` | 3.0 GiB | No | Keep because it is a registered dirty worktree and layered probe scripts still reference it. Remove only its reproducible `triton/build`. |

## Evidence

- The active `hexagon-mlir/triton/.../CMakeCache.txt` sets `LLVM_DIR`,
  `LLVM_INCLUDE_DIRS`, `LLVM_LIBRARY_DIR` and `LLVM_SYSPATH` under
  `LLVM_DIR_upstream/llvm-project/build/install`.
- `scripts/build_hexagon_mlir_incremental.sh` and
  `scripts/build_omnifetch_upstream.sh` default to `LLVM_DIR_upstream`.
- The removed top-level `.mlirbc` files were absent from `git ls-files` and are
  regenerated by the model runners.
- Legacy LLVM changes were based on commit `064f02dac0c8` and are recoverable
  from `third_party_software/patches/llvm-dir-legacy-aligna-20260820.patch`.
- `hexagon-mlir-legacy` contains modified tracked files and unique scripts,
  documents and result records; `hexagon-mlir-native` contains nine modified
  tracked files and is listed by `git worktree list`.

No model results or source files are removed from either legacy repository.

## Cleanup result

- Removed the 12 top-level runner-generated `.mlirbc` files (about 5.2 GiB).
- Removed `LLVM_DIR` (15 GiB) only after validating and preserving its local
  two-file patch.
- Removed reproducible Triton build/cache trees and legacy top-level MLIR
  bytecode. `hexagon-mlir-legacy` decreased from 16 GiB to 6.5 GiB and
  `hexagon-mlir-native` from 3.0 GiB to about 479 MiB.
- Repointed `LLVM_DIR_upstream` to the official LLVM GitHub remote, removed its
  stale object-alternate reference to the deleted `LLVM_DIR`, fetched the
  upstream object database, and verified that every object reachable from
  `HEAD` is present.
- The interactive environment still exported the obsolete
  `LLVM_PROJECT_BUILD_DIR=.../LLVM_DIR/llvm-project/build`. Override it with
  `.../LLVM_DIR_upstream/llvm-project/build` (or unset it) in existing shells;
  fresh invocations of `scripts/build_hexagon_mlir_incremental.sh` already
  default to the upstream tree. An incremental build against that tree passed.
- Workspace usage decreased by approximately 27 GiB. All removed artifacts are
  reproducible; the only non-generated LLVM changes remain recoverable from the
  committed patch.
